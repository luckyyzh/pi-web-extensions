# pi-better-background-tasks 本地修复

- 官方基线：`pi-better-background-tasks@0.2.12`（npm 发布包）。
- `src/` 是当前已使用的修复后源码；保留上游 MIT `LICENSE`。
- 保留 Windows 无弹窗启动、真实退出码恢复、取消处理及原有工具定义；新增完成通知去重与轮次级投递。
- `manifest.json` 记录官方文件和修复文件的 SHA-256。安装清单指定本补丁后，四个文件先全部校验，再写入；当前文件既不是对应官方基线、已发布修复（可选 `previous` 哈希数组），也不是目标修复时，拒绝覆盖。
- 不直接使用旧机器上的增量 patch：旧 patch 的起点已经有更早的修复，不能应用到原版 npm 包。
- 补丁文件通过 `.gitattributes` 禁止换行转换，确保 Windows/macOS/Linux 的校验一致。

升级流程：先审查新的 npm 版本，再更新安装清单、官方基线 SHA-256 和修复源码/校验值。同版本修复升级时，将上个已发布修复的 `after` 哈希列入 `previous` 数组。不要简单修改版本号或直接执行全局 `pi update --all` 来覆盖这些文件。

## 完成通知修复

- 模型/工具忙碌时，完成事件留在插件队列，不提前放入 Pi 的 `followUp` 队列。工具轮次结束后重新检查已读状态，合并为一条 `steer` 消息；空闲时仍按原短窗口自动通知，不轮询等待。
- 原会话通过 `bg_task_status`、`bg_task_log` 或两个 action wrapper 读取终态结果，且该工具结果已成功完成、未被改写/中止后，才写入现有 `callbackSuppressedAt` 字段。日志读取必须取得非空内容，并在返回中明确附带终态和退出码；空/不可读日志不算已读。
- `list`、运行中查询、UI 查看、其它会话读取以及无法确认归属的旧任务不确认消费。失败任务也只有结果确实读到才抑制，不能把失败当成功。
- Windows 恢复及实际投递前均过滤已清除、已确认消费的任务。Stop/异常结束后不由旧完成项立即唤醒，保留未读项供后续会话工作恢复；真正 `session_shutdown` 才清内存队列，避免被否决的切换丢失通知。
- 新的 batcher 选项为可选字段；未配置者仍保持上游 `followUp` 行为，urgent 路径不变。没有更改工具名称、参数、描述、注册顺序、system prompt、thinking 或既有历史消息。

### 验证与边界

使用 Node 22.19+（无需额外测试依赖）：

```sh
node --test patches/pi-better-background-tasks/tests/*.test.mjs
```

测试使用真实修复模块和模拟的进程/存储适配器，不启动后台命令、不触发真实会话通知。覆盖忙碌合并、终态已读、各工具入口、失败/中止/异会话、恢复过滤及发送失败重试。

补丁应用后需要 `/reload` 或新建会话；不会自动重载。已经进入旧 Pi 队列的通知无法追溯撤销，不删除历史来消除它们。`callbackSentAt` 仍表示交给宿主，并非模型阅读回执；本修复不承诺跨进程 exactly-once，也不提前标记送达。还未读的旧任务恢复后仍会正常通知。

回滚需恢复备份中的源码与对应旧清单，再重载；旧清单会拒绝直接覆盖不在其哈希白名单内的新源码。

此目录不包含运行时任务、日志、机器配置或备份。
